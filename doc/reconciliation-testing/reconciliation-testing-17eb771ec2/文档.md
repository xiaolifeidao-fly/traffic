# 补齐对账链路自动化验证与上线验收

## 1. 任务目标

本任务只完成「梳理需求」：为 Phoenix Suffer 对账计算、管理 API、定时/指定日期重跑及管理端工作台建立可重复执行的自动化验证和上线验收清单，覆盖金额与汇率精度、日汇总幂等、5% 预警边界、认证授权、流水 CRUD、动态账户主体、日期筛选与重跑。

本阶段仅创建本文档，不修改 `phoenix/` 业务代码、测试依赖、SQL 或部署配置。动作执行必须以前置对账实现已经合入当前工作树为前提；若仍未合入，不得用当前 mock 数据伪造通过结果。

## 3. 前置条件与测试范围

1. 前置任务 `reconciliation-backend-dcbf2ae425`、`reconciliation-backend-c031403fbb`、`manager-reconciliation-cc1bff031d`、`manager-reconciliation-df602bf0df` 的实际代码、路由、资源 SQL 与管理端 API 接入必须先合入当前分支；动作执行开始时先用文件和编译结果确认，而不是只以任务状态为准。
2. 本任务验证已确认的对账规则和接口行为，不重新设计订单状态、流水类型归属、主体映射、系统欠款公式、预警状态机或权限模型。业务字典缺失时，应验证执行失败、快照回滚和可定位日志，不能以零值计算成功。
3. 测试数据必须使用独立数据库/Schema 或每例可清理的前缀与事务，不连接生产库；测试日期固定为明确的上海自然日，禁止依赖机器当前日期或当前时区。
4. 测试必须经过真实 Service、Repository、Gin Router 和管理端 API 层；可以为外部依赖使用受控 stub，但不得以 `reconciliation.mock.ts`、浏览器本地状态或手工改 DOM 替代后端计算结果。

## 4. 需交付的内容

### 4.1 后端计算与重跑自动化测试

在前置实现落地的 `phoenix/server/suffer/service/reconciliation/` 中补充相邻包级 `*_test.go`（按实际文件拆分），并提供可复用的数据库夹具/清理工具。测试必须直接调用日汇总服务及其依赖 Repository，至少覆盖：

1. **金额、汇率和公式：**使用 decimal 字符串构造含小数的 RMB、U、手续费和汇率样本，断言保存和返回值没有 `float64` 舍入；验证汇率/配置快照与 `calc_version` 写入日汇总，而不是查询时重新读取当前配置。
2. **5% 边界：**同日、同主体、同账户字段分别验证：系统非零的相对差、系统为零且人工非零的 100%、两者为零的 0%、恰好 5% 不触发、超过 5% 才触发预警；同时断言记录保存实际阈值。
3. **幂等与事务：**对同一 `statDate` 连续执行两次，断言人工/上游日汇总、系统账户状态和预警按自然键更新而非重复插入，执行日志可追踪；故意缺少价格、汇率、主体/来源映射或制造持久化错误时，断言业务快照回滚、日志带稳定错误码且修复数据后可重跑。
4. **串行重跑与日期：**固定 `Asia/Shanghai` 时钟验证 `00:10` 自动计算前一自然日；验证合法指定日期、空值、非法格式和未来日期；并发触发同一天 cron/手工重跑时，断言只有一个租约持有者执行，其他调用获得“正在执行”的日志标识，不能并发写快照。

测试不能把 `account_detail`、dashboard 聚合或已有 mock 数据作为对账结果的替身；数据来源与口径须与前置 `reconciliation` 模型一致。

### 4.2 对账 API 与权限集成测试

在实际对账 Handler/Routing 所在模块增加 Gin + `httptest` 集成测试，使用真实认证中间件、已加载的资源记录和隔离测试数据。以已合入的实际 DTO 与 URL 为准，至少验证：

1. 工作台查询：概览、人工/上游日汇总、系统/人工账户状态、流水和预警的正常响应、空结果、日期倒置/非法日期、分页边界与日期过滤；查询只能返回已经落库的快照，不能触发重新汇总。
2. 流水 CRUD：创建、按 ID 更新、逻辑删除、按日期/类型/类目/主体筛选；写入后读取结果应保持 decimal 字符串精度，外部来源幂等字段和服务端审计字段不能由普通请求覆盖。
3. 动态主体与人工账户状态：启用主体可选、停用主体被拒绝；首次创建人工状态使用服务端主体快照；同一 `(recordDate, subjectId)` 重复写入得到明确冲突；系统账户状态没有新增、修改或删除接口。
4. 指定日期重跑：`POST /reconciliation/daily-summary/rerun` 与定时任务走同一计算入口；成功、参数校验失败、运行中冲突、业务字典缺失和数据库失败均断言稳定响应与执行日志关联，不产生半成品快照。
5. 权限：无 token、无匹配资源、拥有管理员资源、资源模板含 `:id` 的访问逐一断言；所有 `/reconciliation` 写接口不得公开。若当前权限模型无法区分同模板的读写方法，验收管理员全量授权以及非管理员拒绝写入，不把“隐藏按钮”视为授权通过。

### 4.3 管理端自动化回归

前置管理端接入完成后，移除工作台对 `reconciliation.mock.ts` 的运行时依赖，并将金额字段改为与 API 一致的 decimal 字符串展示/传输模型。因为当前工程没有前端测试脚本，动作执行必须在 `phoenix/client/manager/package.json` 增加一个可在 CI 非交互运行的测试命令，并采用与当前 Next/TypeScript 兼容的测试工具；工具和最小依赖须在同一变更中锁定。

管理端自动化测试至少覆盖：

1. 页面初始加载、日期范围变更、刷新和空/错误状态都调用真实 API 层；请求失败不得回退为 mock 或旧本地计算结果。
2. 流水新增、编辑、删除成功后完整刷新概览、明细与预警；失败时不乐观伪造成功，保留可恢复的表单/错误提示。
3. 账户主体选择、创建后再录入人工账户状态、重复自然键冲突、停用主体和服务端校验错误均有可见反馈；已有状态记录不可在前端绕过服务端修改日期/主体自然键。
4. 金额、手续费、汇率和预警展示不使用 `Number()`、本地 `reduce()` 或本地 5% 逻辑做账务判定；页面仅渲染服务端汇总、差异率和预警结果。
5. 无写权限或 API 返回 401/403 时，写入口按真实权限状态禁用/隐藏且请求失败被正确呈现；直接 API 拒绝由后端集成测试覆盖，前端不承担鉴权替代职责。

### 4.4 上线验收与交付记录

动作执行须新增或更新与测试同目录的运行说明（文件名按实际测试工具确定），列出本地/CI 命令、必需环境变量、测试数据库初始化、资源 SQL 初始化、固定测试数据与清理方式。最终测试报告必须逐项对应本文件的验收标准，并记录：提交版本、执行时间、命令、通过/失败数、失败原因、受影响接口、使用的隔离环境，以及生产上线前后的核查结果。

上线前必须由具备授权的人员在非生产验收环境确认：资源 SQL 已幂等导入、管理员可访问、非授权账户不能写入、上海时区 00:10 调度已注册但服务启动不补跑、指定日期重跑可定位执行日志。生产操作只允许单日受控重跑；首次历史补算、异步队列、指标告警、业务字典补齐属于独立变更，不在本任务临时扩展。

## 5. 设计约束与非目标

1. 不修改或重新解释 Kakrolot、Barry、`account_detail`、`order_record` 和 dashboard 的既有对外契约；不得以 dashboard 展示口径取代对账账务口径。
2. 不允许测试通过真实生产数据、生产 token、生产数据库或未脱敏导出文件运行；所有敏感配置使用 CI/环境注入，不写进测试源码或文档。
3. 不将重跑测试做成依赖 `time.Now()`、执行顺序或睡眠等待的脆弱用例；必须可注入时间、可控并发和稳定测试夹具。
4. 不把纯构建、页面截图或人工点击一次作为“自动化验证”替代；它们只能作为上线验收的补充证据。
5. 本任务不实现新的业务功能、权限模型升级、批量历史补算、异步执行队列或生产监控告警；发现这些缺口只记录为后续任务建议。

## 6. 验收标准

1. 当前分支在执行测试前能确认前置对账后端、路由、资源 SQL 与真实 API 接入均已存在；若任一缺失，测试报告明确标记阻塞并列出缺失路径，不输出“全链路通过”。
2. 后端自动化测试覆盖 decimal 金额/汇率、配置快照、`calc_version`、5% 边界、同日幂等、失败回滚、上海日期计算、并发租约及执行日志；受影响 Go module 的 `go test` 全部通过。
3. API 集成测试覆盖工作台查询、日期/分页校验、流水 CRUD、动态主体/人工账户状态、指定日期重跑及无 token/无资源/管理员/`:id` 模板权限场景；所有 `/reconciliation` 路由均受现有认证中间件保护。
4. 管理端有可由 CI 执行的自动化测试命令，并覆盖初始化/日期筛选/刷新、流水写操作、主体与人工状态、服务端错误、权限拒绝及服务端预警渲染；`build` 与新增测试命令均通过。
5. 测试中恰好 5% 差异不产生预警、超过 5% 产生预警；系统值为零的两个边界按前置口径返回 100% 或 0%，且页面不以本地常量重新判定。
6. 对同一日期重复或并发重跑不会产生重复快照/预警或部分写入；失败响应能关联执行日志，修复测试数据后重跑可成功。
7. 上线验收记录包含固定测试日期、隔离环境、资源初始化、命令和结果；验收环境验证管理员访问、未授权拒绝、00:10 上海调度注册、服务启动不补跑及单日指定日期重跑。

## 7. 风险与待确认

1. **前置代码未落地：**当前仓库实查不到 `service/reconciliation`、`pkg/reconciliation` 和对账路由，管理端也仍依赖 mock。动作执行第一步必须复查这些路径；未合入时本任务只能交付阻塞报告，不能猜测 API 字段或补造测试目标。
2. **业务字典仍是正确性前提：**用户分层单价、汇率、小费、订单/流水类型、主体映射和系统欠款公式若未配置，预期行为是执行失败且留痕。需要业务方提供至少一组可脱敏、可复现的验收样本与期望汇总。
3. **测试基础设施缺失：**管理端当前没有测试运行器，新增前端测试会带来依赖、CI 缓存和浏览器运行环境选择；动作执行需遵循仓库锁文件和 CI 约束，避免同时引入重复包管理器或两套测试框架。
4. **权限粒度限制：**现有认证以 URL 模板资源授权，当前前置文档指出同模板不能天然按 HTTP method 分权。若上线需要只读角色，必须另建权限模型/路由拆分任务；本任务只验证现有模型的真实行为。
5. **调度验收环境：**真实等待每日 00:10 不适合作为 CI 唯一证据；需通过可注入时钟/调度注册断言覆盖，并在验收环境补充配置核查。多实例部署仍以数据库租约为正确性前提。
