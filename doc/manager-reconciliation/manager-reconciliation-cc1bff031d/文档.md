# 对接管理端工作台真实 API 并移除 mock 状态

## 1. 任务目标

本任务仅完成「梳理需求」：将管理端资金出入账对账工作台从本地样例数据和本地业务状态，改为通过 `@/utils/axios` 读取并写入后端 `reconciliation` API；补齐日期区间筛选、首次加载、刷新、错误态和空态，并保留现有 Ant Design 页面结构与录入交互。

动作执行阶段才可修改管理端代码。本阶段不改业务代码，也不实现或补造后端接口。

### 4.3 接口对应关系

| UI 数据/操作 | 后端接口 | 必要规则 |
| --- | --- | --- |
| 页面总体、人工/上游维度、服务端计算值 | `GET /reconciliation/overview` | 必传 `startDate`、`endDate`；历史区间读取已落库快照，不触发前端或请求内重算。 |
| 流水明细及汇总 | `GET /reconciliation/ledger-records` | 传日期区间与实际所需筛选；使用响应内服务端汇总，不在客户端用浮点求和。 |
| 新增/更新/删除流水 | `POST /reconciliation/ledger-records`、`PUT /reconciliation/ledger-records/:id`、`DELETE /reconciliation/ledger-records/:id` | 写入金额/手续费使用后端要求的 decimal 字符串；普通人工入口不传 `sourceType`、`sourceReference`、`importBatch`。 |
| 系统账户状态 | `GET /reconciliation/system-account-statuses` | 只读；不显示编辑、删除或伪造本地修正。 |
| 人工账户状态 | `GET/POST/PUT /reconciliation/manual-account-statuses[/ :id]` | 按日期和主体读取；创建时遵守 `(recordDate, subjectId)` 唯一；更新不改变自然键或主体快照。 |
| 差异预警 | `GET /reconciliation/alerts` | 直接显示服务端计算出的系统值、人工值、差额、差异率、阈值和处置信息；本页面不在本任务内新增处置 UI。 |
| 账户主体选项 | `GET /reconciliation/account-subjects` | 仅允许选择启用主体；实际 query、分页和字段名以合入后的 Handler/DTO 为准。 |

## 5. 交互与状态要求

1. `RangePicker` 不允许空区间；用户确认完整区间后请求所有工作台数据。请求参数必须是 `YYYY-MM-DD`，不能将浏览器本地时分秒直接传给后端。
2. 首次加载、切换日期区间和点击刷新均显示明确加载反馈；刷新必须重新请求当前已生效筛选，而不是恢复内存样例。
3. Hook 必须捕获 `@/utils/axios` 抛出的异常并维护可渲染的错误状态；使用项目现有 `message.error` 提示请求/提交失败，同时在页面保留可见错误说明和“重试”入口，不能静默吞错。
4. 没有返回记录时，各卡片使用 Ant Design `Empty` 表达无数据；不能显示原型数据、虚构合计或将“请求失败”误呈现成“无数据”。
5. 筛选快速变化时，只允许最后一次有效请求写入页面状态，避免旧区间响应覆盖新筛选；写操作进行中禁用重复提交、重复删除和相同表单确认。
6. 读取或写入成功后以服务端返回/重新读取的数据为准；不得乐观地生成本地 ID、依赖 `Math.max(...ids) + 1`，或仅修改前端数组后提示“已保存”。
7. 沿用页面现有中文文案、Ant Design 组件和 `manager-page-stack` / `manager-data-card` 组织方式；本任务只改现有工作台，不新增配置管理页面，也不扩大侧边栏导航。

## 6. 约束与非目标

- 所有 HTTP 请求必须使用 `@/utils/axios`；禁止 `fetch`、临时 mock 接口、手写请求封装和未类型化 `any`。
- 前端只消费后端快照及汇总结果；不在浏览器实现人工/上游维度、账户差异或账务汇总的业务计算。
- 后端 decimal 金额、比例和汇率的接口边界保持字符串，不得以 JavaScript `number` / `Number()` 作为账务计算或回传依据。
- 本任务不实现 `reconciliation` 后端、数据库迁移、权限资源、定时计算、配置 CRUD 页面或预警处置交互；这些属于前置/后续后端或独立页面任务。
- 不为尚未合入的后端接口设置样例回退、假成功提示或固定数据；接口不可用是阻塞，不是前端兜底场景。

## 7. 验收标准

1. `ReconciliationWorkbenchPanel` 和其子组件不再导入、引用或运行时依赖 `data/reconciliation.mock.ts`，该文件已删除且无剩余引用。
2. 新增 API class 文件和工作台 Hook；所有真实 HTTP 调用均经 `@/utils/axios`，没有 `fetch` 或自定义 request。
3. 页面首次进入会以运行时默认日期区间加载，修改完整日期区间和点击刷新会请求当前区间；请求使用 `startDate`、`endDate` 的 `YYYY-MM-DD` 值。
4. 页面把真实概览、流水、系统账户状态、人工账户状态和预警渲染到对应卡片；服务端空结果显示 `Empty`，加载和失败分别有可见反馈，失败可重试。
5. 流水新增、编辑、删除会调用对应 API，表单包含并提交有效 `subjectId`；成功后从服务端刷新，失败不伪造成功或仅留本地修改。
6. 人工账户状态新增与更新符合后端自然键限制；既有记录不能通过 UI 修改日期或主体，预警使用后端查询结果而非前端百分比计算。
7. 金额聚合和差异判断不再通过浏览器 `Number()` 计算；页面展示和写入不会把 decimal 字符串无条件降精度为 JavaScript 浮点数。
8. 在后端前置任务合入并提供可用环境后，运行 `pnpm lint` 与 `pnpm build`（目录：`phoenix/client/manager`）通过；如现有仓库存在无关失败，需记录与本任务改动无关的原始报错。

## 8. 风险与待确认

1. **当前阻塞：后端未合入。** 当前分支没有 reconciliation Service、Handler 或路由，无法对真实 API 发请求并验证字段。动作执行开始时必须先验证前置任务产物，而非根据本文档自行猜测响应 JSON。
2. **账户主体查询形态待代码确认。** 前置文档只固定 `GET /reconciliation/account-subjects` 的资源和业务约束，当前没有 Handler/DTO 可核对其是否分页、状态过滤字段名及返回主体字段；这决定流水和人工账户状态表单的 select 映射。
3. **概览响应映射待代码确认。** 前置任务指定 `overview` 返回人工/上游汇总和服务端总计，但当前没有实际 response class；实施时应以合入的 DTO 建立 class，不得从 mock 行名称反推接口字段。
4. **页面编辑模型需要收敛。** 现有人工账户表格是“整表本地草稿后保存”，而后端没有批量更新接口且禁止改自然键；实施时需改为逐条安全更新或在 API 层明确串行批量策略，并准确报告部分失败。
