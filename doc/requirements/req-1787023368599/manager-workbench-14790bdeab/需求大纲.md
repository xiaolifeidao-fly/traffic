# 工作台真人/低价卡片与类目明细展示休眠延迟量

- 任务键：manager-workbench-14790bdeab
- 所属需求：req-1787023368599 工作台增加-当前进入休眠延迟的单子有多少
- 里程碑：reconciliation-workbench-v1（一期） / 模块：manager-workbench（管理端工作台） / 类型：capability
- 负责人：降龙 / 起始阶段：development
- 前置依赖：manager-workbench-a2923557f0（phoenix suffer 代理休眠延迟量接口）

## 一、任务目标

在新管理端工作台的「真人商品」与「低价商品」两张卡片上，顶部指标区与展开的类目明细表都展示当前进入休眠延迟的单子数量。

## 二、范围与不做的事

范围内：
- 前端 api 层新增取数方法与类型
- 两张卡片的 `detailMetrics` 各加一项「休眠延迟中」
- 展开的类目明细表为这两张卡新增对应列
- 加载/失败降级处理

不做：
- 不新增图表、趋势线、历史对比
- 不改动其他卡片的取数与渲染
- 不改动卡片的类目配置机制（沿用已有 `categoryIds` 配置）

## 四、实现要点

1. `workbench-dashboard.api.ts`：
   - 新增类型 `DelayAssignmentCountSummary`：`total` + `categoryList`（`shopCategoryId` / `categoryName` / `categoryCode` / `count`）
   - 新增 `fetchDelayAssignmentCount(query?: { shopCategoryIds?: string })`，请求 `/barry/workbench-dashboard/delay-assignment-count`
2. `ManagerDashboardPanel.tsx`：
   - `DerivedCategoryDetail` 增加 `delayAssignmentCount: number`，并在初始化空行处（`:2025` 附近的默认值构造）补 0
   - 分别为两张卡发起独立请求，参数取该卡自己的 `configMap[cardId]?.categoryIds`（真人卡默认 `[7,12]`），互不共用
   - `realActualCompleted`（`:2288` 起）与 `lowPriceActualCompleted`（`:2334` 起）的 `detailMetrics` 数组各追加一项：`{ label: "休眠延迟中", value: formatCount(...) }`
   - 按接口返回的 `categoryList` 建 Map，映射填充各自 `detailRows` 的 `delayAssignmentCount`（参照同处 `completedByCategory` 的写法）
   - `buildDetailColumns`（`:2429`）为 `realActualCompleted` 与 `lowPriceActualCompleted` 两个 cardId 增加「休眠延迟中」列
3. 加载与失败：沿用现有各卡独立请求、独立渲染的模式，不阻塞其他卡片；请求失败时该指标与该列降级为 0，卡片其余内容正常渲染。
4. 样式沿用现有 Ant Design 组件与 `formatCount`，不引入新的 UI 依赖。

## 五、前置依赖

- `manager-workbench-a2923557f0`：需要 suffer 已提供 `/barry/workbench-dashboard/delay-assignment-count`。

## 六、验收标准

1. 真人商品与低价商品两张卡分别按自身 `categoryIds` 取数，数值互不串用。
2. 卡片类目配置变更后，休眠延迟量随之变化。
3. 展开的类目明细每行显示该类目的休眠延迟量，各行合计与卡片顶部指标一致。
4. 接口失败时该指标与该列降级为 0，卡片其余内容正常渲染。
5. 沿用现有 Ant Design 样式与工作台刷新节奏，不阻塞其他卡片加载。
