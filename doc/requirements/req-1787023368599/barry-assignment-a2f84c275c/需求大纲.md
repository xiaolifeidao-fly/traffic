## 一、任务目标

在 barry-inner 网关暴露一个内部接口，支持新管理端按 `shop_category_id` 列表（in 查询）一次性取到各类目当前的休眠延迟单量与合计。

## 二、范围与不做的事

范围内：
- inner 网关新增 GET 接口
- `barry-order-service` 服务层与 DTO
- 批量读取任务一建立的类目集合

不做：
- 不改动现有 `/workbench/dashboard/*` 接口的行为与返回结构
- 不新增数据库表或查询
- 不做历史趋势、分页

## 四、实现要点

1. Controller 新增：
   ```
   GET /workbench/dashboard/delay-assignment-count?shopCategoryIds=7,12
   ```
   参数解析沿用同文件 `taskRemaining` 的写法（`@RequestParam(required=false) String shopCategoryIds`），返回 `WebResponse<...>`。
2. 服务层在 `WorkbenchDashboardService` 增加对应方法，内部：
   - 解析逗号串为类目 id 列表
   - 一次性批量读取各类目集合的 `SCARD`（不逐个往返、不查库）
   - 用 `ShopCategoryService` 补 `categoryName` / `categoryCode`
3. 返回 DTO（新建于 `barry-order-service-api` 的 dto 包）：
   - `total`：合计
   - `categoryList`：`shopCategoryId` / `categoryName` / `categoryCode` / `count`
   - 字段命名与 `WorkbenchDashboardMetricDTO` 保持一致风格，便于 phoenix 直接反序列化
4. 入参为空或类目不存在时返回 `count = 0`，不抛异常。
